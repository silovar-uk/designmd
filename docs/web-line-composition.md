# Webの行と文章の設計

対象：AIが生成・編集するWebページ、LP、コラム、特設サイト、Web資料、HTMLスライド。

> 紙を模倣せず、紙が培ってきた「読みやすく組む判断」を、変化する画面の上で再構成する。

Webの一行は固定された版面の部品ではない。文章、画面幅、文字倍率、書体、ブラウザ、読者の設定が出会った瞬間にだけ成立する一時的な形である。

したがって制作者が固定するのは、すべての行末ではない。**壊してはいけない意味、読みの優先順位、調整の順序、破綻しない下限**である。

---

## 1. 基本思想｜「改行できる」と「そこで改行したい」は別

Unicode Line Breaking Algorithm が示すのは、主として「どこなら改行可能か」という候補である。実際にどの候補を選ぶかは、使える幅、文字サイズ、レイアウト、美的・編集的な基準を知る上位の処理へ委ねられる。

この区別をDesignMDの出発点にする。

> **規則上そこで切れることと、読み手にとってそこで切るべきことは同じではない。**

日本語は欧文のように単語間スペースだけで改行位置が決まらない。そのため、ブラウザが合法な位置で折り返していても、固有名詞、長い外来語、複合語、文節、意味のまとまりが視覚的に壊れ、不自然に見えることがある。

### 意味は固定し、行は流動させる

AIは意味構造を決めてよいが、すべての端末で同じ行末を命令しない。`<br>`は視覚上の固定命令であり、画面幅が変わると二重改行や孤立語を生みやすい。

### 紙の外見ではなく、編集倫理を持ち込む

紙や出版から受け継ぐのは、明朝体、段組み、紙テクスチャではない。

- 読者の注意を雑に扱わない
- 禁則だけでなく、意味単位を壊さない
- 一行ごとの視線移動を考える
- 行長に無理が出たら、何を調整するか順序を持つ
- 重要度を形として示す
- 読ませる速度を意図的に変える

W3Cの日本語組版処理の要件（JLREQ）にも、禁則などによって行長に過不足が生じた場合に、字間を詰める・空けるなどの「行の調整処理」が整理されている。つまり組版は、文字を箱へ押し込むことではなく、**制約の中で複数の変数を調整する仕事**である。

### 組版は透明だが、中立ではない

文字組みは内容を邪魔しない器である一方、何を先に見せ、どこで止め、どこを同じまとまりとして扱うかを決める。目立たなくてよいが、無自覚であってはいけない。

### Web固有の変化を受け入れる

Webは画面幅、文字拡大、入力方法、読み上げ、縦横切替によって姿を変える。完成時のスクリーンショット一枚ではなく、**変化しても編集意図が薄まらないこと**を品質とする。

## 2. 五層で改行を判断する

改行判断を、次の五層に分ける。上ほど「守るべき条件」、下ほど「編集上の最適化」に近い。

### Layer 1｜規則

禁則、文字クラス、分割禁止など、組版上の基本条件を守る。

- 行頭へ閉じ括弧や句読点を不自然に出さない
- 行末へ開き括弧を残さない
- 連続するダッシュ、省略記号を不用意に分割しない
- 欧文単語を理由なく文字単位で分割しない

ここは「好み」より先に確認する。

### Layer 2｜語

短い表示文字では、固有名詞、商品名、サービス名、長い外来語、認識に時間のかかる複合語を不用意に壊さない。

```text
避けたい例
ユーザーエクスペリエ
ンスを改善する
```

ただし、日本語本文のすべての語を英語の単語のように絶対分割禁止へはしない。保護を強くするのは、見出し、キャプション、ボタン、カード見出しなど、**一目で意味の塊を認識させたい場所**である。

### Layer 3｜意味

単語だけでなく、文節やフレーズのまとまりを見る。

```text
細切れ
AIがつくった
ページで感じる
日本語改行の
違和感

意味を優先
AIがつくったページで感じる
日本語改行の違和感
```

改行回数を増やすほど丁寧になるわけではない。短い行が連続すると、各行が独立した主張のように見え、読みの速度も不必要に止まる。

### Layer 4｜リズム

一行だけでなく、複数行全体を一つの形として確認する。

- 最終行だけ極端に短くないか
- 一語だけ孤立していないか
- 2〜3行で読める内容を4〜5行へ分割していないか
- 改行によって意図しない語が強調されていないか
- 長短の差が大きすぎて、読みのリズムが乱れていないか

`text-wrap: balance` や `pretty` は、この「合法な候補の中から、よりよい折り返しを選ぶ」方向をWebへ持ち込む手段になる。ただし対応差を前提に漸進適用する。

### Layer 5｜適応

PCで美しい位置を、スマートフォンへ固定しない。

同じ文言でも、320pxと1440pxでは自然な行末が違う。200％文字拡大でも変わる。固定するのは意味の境界であり、最終行末はできるだけブラウザへ委ねる。

## 3. 文章の役割ごとに折り返し方を変える

| 要素 | 目安 | 折り返し方針 |
|---|---:|---|
| 大見出し | 1〜3行、約12〜22字／行 | 意味単位を優先し、`balance`を漸進適用 |
| 小見出し | 1〜3行、約14〜26字／行 | 内容を特定できる文言にし、孤立語を避ける |
| リード | 全角24〜32字程度／行 | 本文より狭くし、結論と読み進める理由を置く |
| 本文 | 全角28〜36字程度／行 | 禁則、十分な行間、自然な右端を優先 |
| 引用 | 全角20〜30字程度／行 | 本文より狭くし、発言の呼吸を残す |
| キャプション | 全角20〜32字程度／行 | 画像との関係を一文で説明する |
| ボタン・タグ | 原則1行 | 短く書き直し、意味的に分割しない |
| URL・コード | 内容次第 | 通常文を壊さず、長トークンだけ局所救済 |

数字は絶対値ではない。書体、文字サイズ、読者、媒体、段組みで調整する。文字数を合わせること自体を目的にしない。

---

## 4. 見出しは「文章」ではなく「文章＋構図」として編集する

見出しの折り返しは、ブラウザへ全文を投げて終わりにしない。次の順で見る。

1. 壊してはいけない意味のまとまり
2. 読者が最初に拾う語
3. 上下の行の視覚的な長さ
4. 最終行の短さ
5. 行数
6. 文字サイズの下限

### 避ける状態

- 助詞だけが次の行へ残る
- 2〜4文字だけの最終行が生まれる
- 固有名詞や長い外来語が不自然に分割される
- 数字と単位が離れる
- 1行目が極端に長く、2行目が極端に短い
- 改行が多すぎて、一つの見出しが短文の連射に見える
- スマホだけ文字を極端に縮小して1行へ押し込む
- PC用の固定`<br>`がスマホで二重改行になる

### 固定改行を使える条件

次をすべて満たす場合に限る。

- 見出し自体が短い
- 分割位置に意味上の理由がある
- 主要幅を連続的に確認した
- 200％文字拡大でも意味と操作を損なわない
- CMSや翻訳で文言が変わらない、または変化時の検証がある
- 固定改行を外した時より明確に良い

一つでも満たさなければ、固定改行ではなく、文言、最大幅、折り返し候補、文字サイズ範囲などで調整する。

## 5. 収まらないときの調整順序

「入らないから小さくする」「入らないから途中で切る」の二択にしない。

DesignMDでは、原則として次の順に調整する。

1. **意味のまとまりを確認する**
2. **文言を短くできるか編集する**
3. **コンテナ幅、余白、列数、配置を見直す**
4. **望ましい折り返し候補を調整する**
5. **必要な場合だけ、字間を小さな範囲で調整する**
6. **短い表示文字だけ、定めた下限まで文字サイズを調整する**
7. **それでも難しければ、一行増えることを許す**

この順序は固定アルゴリズムではない。媒体の役割で入れ替わる。

### 文字サイズを下げる方がよい場合

ヒーロー見出し、短いキャッチコピー、固定面積のKV、サイネージなどでは、意味の途中で不自然に割るより、**あらかじめ決めた下限まで少し縮小する方が読みやすい場合がある**。

条件：

- 対象が短い表示文字である
- 最小文字サイズを先に決めている
- 1段階または少数段階の調整に留める
- 下限を超えたら、縮小を続けず行数を増やす
- 文字拡大、狭幅、長い固有名詞で再検証する

### 本文では縮小を解決策にしない

本文を文字列ごと・段落ごとに小さくして収めると、読みの一貫性とアクセシビリティを壊しやすい。本文は基本文字サイズを守り、行幅、余白、レイアウト側で解決する。

出版組版にある「行長に合わせて調整する」考え方を借りつつ、Webでは**読者の文字拡大を打ち消さない**ことを優先する。

## 6. 折り返さない単位と、折り返し候補を限定する

### `nowrap`は局所的に使う

`white-space: nowrap`はレイアウトを支配する命令ではなく、短く分割不能な単位を守るために使う。

適用候補：

- 人名、短い固有名詞
- 日付、時刻
- 数字＋単位
- 章番号
- 短いタグ
- ボタンラベル
- スコア、比分

```html
<p>来場者数は<span class="no-break">52,000人</span>でした。</p>
```

長い見出しや本文全体へは使わない。

### 強制改行より、任意改行候補を先に考える

特定の短い見出しで、編集上望ましい境界を示したい場合は、`<br>`で必ず切る前に `<wbr>` で「ここなら切ってよい」と示せないか検討する。

```html
<h1>日本語の改行を<wbr>意味から設計する</h1>
```

幅があれば一行のまま、必要な場合だけその候補を使える。

## 7. Web実装の基礎

### 言語を明示する

```html
<html lang="ja">
```

言語依存の組版処理を使うため、日本語ページの言語を明示する。

### 本文は通常折り返しを壊さない

```css
.article-body,
.article-body p,
.article-body li {
  max-inline-size: 36em;
  line-height: 1.8;
  line-break: strict;
  word-break: normal;
  overflow-wrap: normal;
}
```

`word-break: break-all` や `overflow-wrap: anywhere` を本文全体の通常設定にしない。長いURL、コード、識別子など、本当にオーバーフローする要素だけへ局所適用する。

```css
.long-token {
  overflow-wrap: anywhere;
}
```

### 短い見出しはフレーズ単位と全体バランスを試す

```css
.article-title,
.section-title {
  max-inline-size: 18em;
  line-break: strict;
  word-break: normal;
  overflow-wrap: normal;
  text-wrap: balance;
}

@supports (word-break: auto-phrase) {
  .article-title,
  .section-title {
    word-break: auto-phrase;
  }
}
```

CSS Text Level 4 では `word-break: auto-phrase` が、言語固有の解析によって自然なフレーズ内の折り返しを抑えるための値として定義されている。短い見出しやキャプションと相性がよい。

ただしCSS Text Level 4はWorking Draftであり、実装差がある。**意味の成立を未対応機能へ依存させない。**

### `text-wrap`も漸進適用する

`balance` は短い見出しの複数行を均衡させる用途、`pretty` は本文などでより良い折り返しを選ぶ用途の候補になる。

未対応環境では通常の折り返しに戻っても読めることを前提にする。

### 文字サイズは範囲として設計する

```css
.hero-title {
  font-size: clamp(2rem, 6vw, 5rem);
  line-height: 1.12;
  text-wrap: balance;
}
```

`clamp()`は文字列を検出して「入るまで無限に縮める」仕組みではない。閲覧条件に応じて、事前に決めた上限・下限の中で変化させるために使う。

## 8. AIへ渡す構造

AIへHTMLを直接一発生成させる前に、主要な表示文字について次を整理させる。

```text
見出し本文：
役割：内容説明／解釈／判断／転換
最大行数：
意味のまとまり：
分割を避けたい語：
折り返し候補：
固定改行が必要か：原則不要
最小文字サイズ：
スマホで短縮可能な表現：
```

AIの役割は、最終的なピクセル位置を固定することではなく、**何を守り、どこを流動させ、崩れた時に何から調整するかを決めること**である。

### AIの禁止事項

- 意味上の理由なしに`<br>`を入れる
- すべての見出しへ固定改行を入れる
- 日本語本文を細切れの短行へする
- `word-break: break-all`で問題を隠す
- 本文を収めるため文字サイズを小さくする
- 短い表示文字も、下限なしで入るまで縮め続ける
- PCのスクリーンショットだけで完成判定する
- 全文を同じ`max-width`、同じ行間で扱う
- ボタンを2行にして文言の長さを放置する

## 9. Web文章の読み方を設計する

Webでは精読だけでなく、探索、比較、判断、行動のためにも文章が読まれる。すべてを短く切るのではなく、読者が読み方を切り替えられる構造を作る。

- 見出しだけを読んでもページの論理が追える
- 各段落の冒頭に対象または判断を置く
- 重要情報を右側や段落末尾だけへ隠さない
- 精読させたい本文は十分な行幅と余白を持つ
- 行動文は、対象、条件、操作、結果を明確にする
- カード化は独立した入口に限り、連続文章を細切れにしない

**段落を分けることと、表示上の行が折り返されることは別の設計問題である。**

意味や論証が変わるなら段落を分ける。同じ段落の中でどこに行末が来るかは、組版とレイアウトへ委ねる。空きを作るためだけに文章へ`<br>`を入れない。

```text
分割を避けたい語：
折り返さない要素：

意味 → 文言 → 幅・余白・配置 → 折り返し → 字間 → 表示文字サイズ → 行数追加
```

## 11. 品質検査

### 幅を連続的に動かす

代表幅のスクリーンショットだけでなく、320pxから1440pxまでブラウザ幅を連続的に動かす。変な状態はブレークポイントの間に出やすい。

### 必須確認

- 320、375、768、1024、1440px
- 200％文字拡大
- OSの文字サイズ変更
- 日本語と英数字が混ざる見出し
- 長い固有名詞、外来語、URL、数値＋単位
- CMSで最長文言を入れた状態
- `auto-phrase`が効く環境／効かない環境
- 読み上げ、キーボード操作

### 見出しレビュー

- 見出しだけでページの論理が追えるか
- 語や意味の途中で不自然に切れていないか
- 最終行が極端に短くないか
- 助詞や接続語が孤立していないか
- 固有名詞、数字、単位を壊していないか
- 改行を使いすぎて、短文が連射されていないか
- 手動`<br>`を外した方が安定しないか
- 幅変更時に文字サイズが過剰に変化しないか
- 縮小より行数追加の方が読みやすくないか

### 本文レビュー

- 行末から次の行頭へ視線を戻しやすいか
- 行幅に対して行間が狭すぎないか
- 段落が長すぎて探索点を失っていないか
- 短い段落・手動改行を演出的に増やしていないか
- URL対策のために通常の日本語まで文字単位で割っていないか
- 文字サイズを下げてレイアウト問題を隠していないか

### 借りたもの

- JLREQ：禁則だけでなく、行長に過不足が出たときに複数の調整手段を持つという考え方
- Unicode UAX #14：改行候補の判定と、実際の改行位置の選択を分ける考え方
- CSS Text：フレーズ単位の改行、複数行全体のバランスをブラウザで扱う方向性
- Webデザイン論：固定版面ではなく、画面の可変性を前提にする考え方

### 借りていないもの

- 紙の固定版面をそのままWebへ移すこと
- すべての日本語単語を分割禁止にすること
- Working DraftのCSS機能が全環境で使えるという前提
- 文字サイズや一行文字数を普遍的な正解として固定すること

外見を模倣せず、**判断方法だけをDesignMD向けに再編集する。**
