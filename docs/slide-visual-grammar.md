# スライドの視覚文法

> 状態：experimental  
> 最終更新：2026-08-13  
> 目的：一枚ごとの「見た目」ではなく、資料全体で再利用できる視覚ルールとページパターンを定義する

この文書は [`slide-blueprint.md`](slide-blueprint.md) の後、PowerPointや画像生成へ入る直前に使う。

> テンプレートを選ぶのではなく、共通文法を固定し、ページごとにパターンを選ぶ。

同じ資料の中で全ページを同じ構造にする必要はない。一方で、ページごとに自由にしすぎると資料としての読み方が失われる。そこで、**全ページで共有するもの**と、**ページ役割によって変えるもの**を分ける。

---

## 1. 二層で考える

### 層A｜共通文法

資料全体で原則として共有する。

- 明度階層
- 文字サイズの段差
- 余白の基準
- 色の意味
- 図形・矢印の意味
- 画像の役割
- 反復モチーフの意味
- フェーズ転換の表し方

### 層B｜ページパターン

ページの伝達目的と役割に応じて選ぶ。

- 段階診断
- 比較
- 障害・具体例
- 打ち手→到達状態
- 現在地ナビ
- 因果・プロセス
- 全体フロー
- 結論・判断

> 共通文法は「同じ資料に見せる」ために使い、ページパターンは「その一枚の仕事を成立させる」ために変える。

## 2. 共通文法

### 2-1. 色は「何色か」より、面積と明度差を先に決める

色は次の四層で考える。

1. **基底面**：最も広い。白、オフホワイト、ごく淡い色
2. **構造面**：カード、帯、章のまとまり。基底面との差は小さくする
3. **アクセント面**：現在地、数字、矢印、重要な印。面積を狭くする
4. **前景**：本文、タイトル。最も高い可読性を確保する

実制作では色相を先に決めず、まずグレースケールで強弱が成立するかを見る。

#### 面積の目安

固定比率ではなく、初期検討のレンジとして扱う。

```text
基底面      55〜80％
構造面      10〜25％
アクセント   2〜8％
画像・図版    5〜20％
```

合計はページによって重なるため100％に揃えない。

重要なのは、**広い面ほど弱いコントラスト、狭い面ほど強いコントラストを許せる**という関係である。

### 2-2. 同系色は三段階まで

同じ色相を使う場合、次の役割へ分ける。

```text
淡い：背景・構造
中間：案内・現在地・大きな記号
濃い：小さな強調
```

同じ彩度の色面を複数並べない。面積の大きい色と小さい色が同じ強度だと、複数の主役が発生する。

### 2-3. 文字サイズは「少しずつ」ではなく、役割ごとに段差をつくる

本文を1とした目安：

```text
注釈・フッター    0.65〜0.8
本文              1.0
カード見出し      1.4〜1.7
スライドタイトル   2.4〜3.4
ヒーロー数字・短語  8〜16相当の視覚高
```

ヒーロー数字は実フォントサイズではなく、画面上の占有高さで考える。

#### ルール

- 本文、見出し、タイトルの差が目視で即座に分かること
- 主役を大きくするために本文を小さくしない
- 同じ階層に三種類以上のサイズをつくらない
- 太さだけで階層をつくらず、サイズ、位置、余白も使う

### 2-4. 一枚に「巨大なもの」は原則一つ

巨大数字、大見出し、大写真、大グラフを同時に主役にしない。

巨大要素を使う条件：

- 番号そのものに意味がある
- 数値そのものに意味がある
- 短い結論語そのものがページの中心である
- 写真そのものが証拠である

「見栄えが寂しいから」は理由にしない。

### 2-5. 余白を区切り線の代わりに使う

余白には三種類ある。

- **外周余白**：スライドと内容の境界
- **群間余白**：意味の違うグループの境界
- **群内余白**：同じグループの内部

基本関係：

```text
群内余白 < 群間余白 < 外周余白
```

近接だけで意味が分かるなら、罫線やカードを足さない。

### 2-6. 一枚に支配的な読み方向を一つつくる

例：

```text
左 → 右        時系列、変化、提案
上 → 下        階層、原因から結果、説明
中央 → 周辺    中心概念と構成要素
左右比較       A/B、Before/After
```

矢印を使う前に、配置だけで方向が分かるか確認する。矢印は関係を補強するために使い、関係を捏造しない。

### 2-7. 反復モチーフは「装飾」ではなく状態を持たせる

シリーズで同じ形を反復する場合、次のいずれかを担わせる。

- 現在地
- 進捗
- 章
- 同じ分類軸
- 比較軸
- 状態変化

意味のないロゴ的モチーフを毎ページ置かない。

### 2-8. 背景の変化はフェーズ転換へ使う

同じ資料内で背景色や基調を変える場合、次のような意味の切り替えと対応させる。

- 問題 → 解決
- 事実 → 解釈
- 観察 → 判断
- 本編 → 付録
- 現状 → 未来

ページごとの気分転換としてランダムに変えない。

### 2-9. 画像の役割を一語で言えるようにする

```text
証拠 / 現物 / 具体例 / 状態 / 比較 / 空間 / 人物
```

これ以外で「雰囲気」のためだけに置く場合は、削除候補とする。

### 2-10. 低コントラスト面へ意味を依存させない

淡いカード、色面、薄い線は、グループ化や雰囲気づくりには使える。ただし、重要な区別を色差だけで表さない。

- 位置
- 余白
- 見出し
- 形
- ラベル

を併用する。

## 3. 「何を伝えるか」のパターン

ページの意味上の仕事を先に選ぶ。

### S1｜段階診断

読み手に「どこで止まっているか」を理解させる。

構成要素：

- 段階番号または短い段階名
- 現在地
- 症状または失敗状態
- 具体例1〜2件

向く役割：見る / 考える

### S2｜比較・反転

AとB、現状と理想、前半と後半の違いを理解させる。

構成要素：

- 共通比較軸
- 左右または上下の二群
- 差分を示す短い結論

向く役割：比べる / 決める

### S3｜障害・具体例

抽象的な問題を、現場で起きる状態へ落とす。

構成要素：

- 問題の短い定義
- 1〜2個の具体例
- 必要に応じて人物・画面・現物

向く役割：見る / 考える

### S4｜打ち手→到達状態

施策と、施策後に目指す状態をつなぐ。

構成要素：

- 現状または段階
- 打ち手1〜4件
- 変化の方向
- 到達状態
- 到達状態の確信度：実績 / 目標 / 仮説

向く役割：決める / 進める

### S5｜現在地ナビ

複数ページのシリーズで、読み手がどこにいるかを示す。

構成要素：

- 3〜5段階
- 現在地
- 必要に応じて完了済みと未到達の差

向く役割：進める

### S6｜因果・プロセス

流れ、分岐、条件、戻りを理解させる。

構成要素：

- 起点
- 主要ノード
- 条件
- 結果
- 例外または戻り

向く役割：考える / 決める

### S7｜全体回収

これまで個別に見た内容を、一枚で構造化して回収する。

構成要素：

- 既出概念のみ
- 全体関係
- 次に参照する場所

向く役割：進める / 考える

新情報を大量に追加しない。

## 4. 「どう見せるか」の構図パターン

意味パターンと別に選ぶ。

### V1｜Hero + Evidence

```text
┌──────────────────────────┐
│ 大きな番号 / 短語   タイトル          │
│                                      │
│ 進捗          [具体例]   [具体例]      │
└──────────────────────────┘
```

向く：S1、S3

注意：巨大要素が意味を持つ場合だけ。

### V2｜Action → Outcome

```text
┌──────────────────────────┐
│ 番号＋タイトル                             │
│          打ち手      →      到達状態        │
│ [既存課題] [既存課題]        [図・人物]     │
└──────────────────────────┘
```

向く：S4

注意：右側の到達状態が事実・目標・仮説のどれかを明示する。

### V3｜Split Contrast

```text
┌─────────────┬─────────────┐
│ A / 現状 / Before │ B / 理想 / After  │
│ 根拠              │ 根拠              │
└─────────────┴─────────────┘
```

向く：S2

注意：左右で比較軸を揃える。

### V4｜Sequence Navigator

```text
[1]──[2]──[3]──[4]
              ↑ current
```

向く：S1、S5

注意：ナビだけで画面を占有しない。段階を覚える価値があるシリーズに限定する。

### V5｜Decision Flow

```text
[起点]
  ↓
◇ 条件？ ──→ 結果A
  ↓
◇ 条件？ ──→ 結果B
  ↓
結果C
```

向く：S6、S7

注意：線が交差するならページ分割か表形式を検討する。

### V6｜Single Claim + Proof

```text
┌──────────────────────────┐
│          結論・判断                          │
│                                              │
│   根拠1        根拠2        根拠3             │
└──────────────────────────┘
```

向く：判断・承認、最終提案

注意：根拠以上にタイトルを強くしない。

## 5. 意味パターン × 構図パターン

最初の候補：

```text
S1 段階診断       → V1 / V4
S2 比較・反転     → V3
S3 障害・具体例   → V1 / V3
S4 打ち手→到達   → V2
S5 現在地ナビ     → V4
S6 因果・プロセス → V5
S7 全体回収       → V5 / V6
```

これはテンプレート対応表ではない。内容に合わなければ使わない。

## 6. 同じ資料の中で「固定するもの」と「変えるもの」

### 固定する

- 文字ファミリー
- 色の意味
- 本文サイズの下限
- 注釈・出所のルール
- 同じ役割の図形
- 同じ分類軸のラベル
- 余白の基本単位

### 変える

- 一枚の構図
- 情報密度
- 主役の種類
- 画像の大きさ
- 背景の基調
- 読む速度
- タイトルの強度

統一は「同じレイアウト」ではなく、**同じ判断ルールが見えること**でつくる。

---

## 7. 資料全体のリズム

一枚ずつ良くしても、全ページが同じ密度・同じ構図だと資料全体が平板になる。

3〜5ページ単位で次を確認する。

```text
静：余白が多い、短い主張
標準：説明と根拠が均衡
密：比較表、フロー、データ
動：変化、転換、大きな図版
```

「静→標準→標準→密→静」のように、読む速度を変える。

背景変更、大写真、巨大数字など強い手法を連続させない。

---

## 8. 実装前チェック

### 共通文法

- 色を消しても優先順位が分かるか
- 基底面、構造面、アクセント面の役割が分かれているか
- 本文とタイトルに十分なサイズ差があるか
- 巨大要素が二つ以上競合していないか
- 群内、群間、外周の余白に差があるか
- 読み方向を一文で説明できるか
- 反復モチーフに意味があるか
- 背景変更が物語上の転換と対応しているか

### パターン

- ページの意味パターンを一つ選べるか
- 構図パターンが内容の関係を正しく表しているか
- パターンを使うために内容を変形していないか
- 前後ページと同じ構図が3枚以上続いていないか

## 9. AI・Markdown用メタ記法

これはレンダラー命令ではなく、AIと人間で判断を共有するための記法である。

```markdown
<!-- slide-visual-grammar
purpose: 示唆・解釈
role: 考える
semantic-pattern: S1 段階診断
composition-pattern: V1 Hero + Evidence
hero-anchor: 段階番号
reading-direction: left-to-right
tone-layers: base / structure / accent / foreground
image-role: 状態
sequence-motif: 四段階の現在地
phase: problem
certainty-of-outcome: none
-->
```

改善策ページの例：

```markdown
<!-- slide-visual-grammar
purpose: 行動明示
role: 決める
semantic-pattern: S4 打ち手→到達状態
composition-pattern: V2 Action → Outcome
hero-anchor: 段階番号
reading-direction: left-to-right
image-role: 到達状態の具体例
phase: solution
certainty-of-outcome: target
-->
```

記法を埋めること自体を目的にしない。構図の判断が難しいページだけ使う。

## 10. この文法の由来と限界

この文書の一部は、ユーザー提供の『マニュアル通りに人が動けない4つの落とし穴』スライド群を分析し、別の専門家視点から批判した後に抽出した。

詳細：[`references/manual-slide-grammar-case.md`](references/manual-slide-grammar-case.md)

模倣するのは色や素材ではなく、

- 明度階層
- サイズ差
- 余白
- 意味を持つ反復
- ページ間の反転
- 読み方向

という設計判断である。
