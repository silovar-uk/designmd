# designmd 知識地図とAI参照面

> 状態：experimental  
> 最終更新：2026-08-06

designmdの内容が増えても、巨大な一枚の説明書へ戻さないための情報アーキテクチャを定める。

## 二つの利用面

同じコンテンツから、二つの利用面を生成する。

### 人が使う面

- 地区からテーマを選ぶ
- 編集された散歩道を歩く
- 実践工程から近道する
- 事例へ寄り道する
- ページ末尾から「深く・使う・横道」へ進む

### AIが使う面

- ページID
- type
- status
- topic
- use_when
- avoid_when
- 型付きrelations
- canonical URL
- raw URL
- Context Pack

人間向けの地図表現を、AIの分類語彙としてそのまま使わない。

## 五つの場所

1. 入口広場｜はじめる
2. 散歩道｜読む・探索する
3. 工房｜実践する
4. 展示室｜事例を見る
5. 書庫｜確認する

各ページの正規の住所は一つだけとする。複数のテーマから参照できるが、パンくずは正規の住所で固定する。

## 七つの地区

- 人の判断
- 情報のまとまり
- 文章
- スライド
- Web・アプリ
- AIとの協働
- 運用・回復

地区はテーマ軸であり、ページの保存場所ではない。

## 道の種類

- `deepens`：もう少し深く
- `applies`：実際に使う
- `detour`：少し横道へ

関連リンクを無制限に並べず、ページ末尾では原則として三方向だけを示す。

## 編集された散歩道

散歩道はページの自動推薦ではなく、理解が変化する順番を人が選んだID配列である。

各ルートは次を持つ。

- title
- duration
- mood
- topics
- description
- stops
- 各stopのnote

## データの正典

`data/knowledge-map.json`を、場所、地区、散歩道、Context Pack、ページ別メタデータの正典とする。

本文の正典は`content/`のMarkdownに残す。知識地図データへ本文を複製しない。

## 公開面

現行トップページへ、同じデータを使う知識地図の入口をJavaScriptで追加する。データ取得に失敗しても、最小限の地図を表示する。

今回の公開物：

- `/knowledge-map.html`：地区と散歩道を大きく見る
- `/knowledge-map.json`：場所、地区、関係、散歩道の機械可読データ
- `/ai-reference.html`：AI参照面の人向け案内
- `/ai-manifest.json`：AI向け入口と優先順位
- `/llms.txt`：最小の参照案内
- `/context-packs/{pack}.md`：用途別の参照セット

`/next/`は体系的なガイド・ケース・ツールの図書館として並走させる。今回の地図から既存の`/next/`ページへ接続するが、全ページを地図用に複製しない。

## 新しいページを追加するとき

1. `content/`へ本文を追加する
2. `data/knowledge-map.json`の`content`へ同じIDのメタデータを追加する
3. 正規の`home`を一つ決める
4. `topics`を1〜4件に絞る
5. `use_when`と`avoid_when`を書く
6. `deepens`、`applies`、`detour`を原則一件ずつ選ぶ
7. 必要なら散歩道またはContext Packへ追加する
8. `npm run check`を実行する

## 境界

- 地図をフォースグラフにしない
- ページ数や閲覧数をゲームの達成率にしない
- `case`をstableな規範として扱わない
- `experimental`を見た目だけでstableに見せない
- AIへサイト全体を毎回渡さない
- 人向けの比喩的な場所名だけで、機械的意味を表さない
- 関連ページを増やす前に、道の意味を決める

## 検証

- 地区を選ぶだけで、読み物・実践・事例の違いが分かるか
- 急いでいる人が五工程へ直接入れるか
- ページ末尾の三方向が重複していないか
- AIが`status`と`use_when`から参照優先度を判断できるか
- `llms.txt`とContext Packだけで目的別の参照を開始できるか
- JavaScriptが失敗しても、本文と主要導線が読めるか
