# 議事録

> 状態：stable  
> designmd版：2026.08.04-beta  
> 最終更新：2026-08-04

議事録は、会議を魅力的に見せる文章ではない。会議後に、決定、保留、担当、期限、根拠を確認し、仕事を進めるための記録である。

共有用の議事録では、発言順を再現するより、読み手が短時間で「何が共有され、何が決まり、何を次に進めるか」を把握できる構造を優先する。

## 1. 共有用議事録の基本方針

- 発言者ごとの要約ではなく、案件・論点ごとに整理する
- 決定事項、検討事項、確認事項、次の対応を混ぜない
- 雑談、相づち、言い直し、画面操作の会話は原則として削る
- 判断理由、制約、反対意見が結論に影響する場合は残す
- 固有名詞、金額、日付、人数、正式な企画名は推測で補完しない
- 共有先が部内の場合は、背景を残しつつ、要点のみ簡潔にまとめる
- 自動文字起こしの順序より、会議後の仕事の進めやすさを優先する

議事録は発言録ではない。ただし、誰の判断かが責任や方針に影響する場合は、発言者または担当部署を残す。

## 2. 推奨する書式

部内共有用の標準形は、次の階層を基本とする。

```text
■7月30日 プロモーションMTG 共有事項

1. 全体概要
（会議全体で確認した内容と、特に重要な論点を2〜4文で記載）

2. 主な共有・確認事項
◎案件名
（現状、確認事項、方針、検討内容を短い段落で記載）

■主な案
・案1
・案2
・案3

3. パートナー・新規連携案件
・案件と次の動きを箇条書きで記載

4. 次回に向けた主な対応
・対応内容を箇条書きで記載

次回の全体会は、○月○日○時から実施予定。
```

### 階層記号の役割

- `■会議名・共有事項`：文書全体のタイトル
- `1. 2. 3.`：大項目。会議全体の読み順を示す
- `◎案件名`：主要案件・議題の見出し
- `■主な案`：案件内の案、内訳、確認対象をまとめる小見出し
- `・`：同じ役割の項目を並べる箇条書き

記号は装飾ではなく、情報の階層を示すために使う。同じ階層で記号を混在させない。

## 3. 基本構成

### 1. 全体概要

会議で扱った範囲と、特に重要な判断・方針を先に示す。

- 2〜4文を目安とする
- 個別案件の詳細を詰め込まない
- 「何を確認した会議か」「どの方針が重要か」を示す
- 単なる目次や議題一覧にしない

例：

> 各ホームゲームの集客状況、イベント施策、発信計画、パートナー連携案件などの進捗を確認。  
> 特に、9月のイベントと12月の企画について、イベントとPRが早い段階から連携して進める方針を確認。

### 2. 主な共有・確認事項

案件別に、状況、判断、検討、次の動きをまとめる。

```text
◎案件名
現状または確認した事実。
決定・方針・検討内容。
必要に応じて、次の対応や期限。
```

一つの案件を一つのまとまりとして扱い、別案件の情報を同じ段落へ混ぜない。

### 3. 関連案件・新規連携案件

本文で詳述するほどではないが、共有と追跡が必要な案件をまとめる。

- パートナー案件
- 新規企画
- 他部署との連携
- 追加予算や提案状況
- 開催時期の確認

同じリスト内では、「状況一覧」「対応一覧」など役割をそろえる。

### 4. 次回に向けた主な対応

会議後に動く内容だけをまとめる。

- 対応内容
- 担当または関係部署
- 期限
- 次回の判断事項

担当や期限が不明な場合は、推測せず「担当要確認」「期限要設定」と記載する。

## 4. 文体と文末

共有用議事録では、丁寧語を重ねず、短く客観的に記載する。

使いやすい文末：

- 確認
- 検討
- 調整
- 実施予定
- 見込み
- 方針
- 必要がある
- 進める
- 確認する

例：

```text
チケット販売は一定の動きがあるものの、目標に対しては不足している状況。
既存クリエイティブを活用した追加広告について、見積もりと配信シミュレーションを確認し、実施判断を進める。
```

体言止めを増やすこと自体を目的にしない。責任、期限、条件、次の行動が重要な箇所では、動詞まで書く。

### 避ける表現

- 「〜という話があった」「〜とのことだった」の連続
- 「今後検討していく」のように、担当・対象・判断時期が見えない表現
- 会議の雰囲気を演出する感想
- 必要以上の敬語、前置き、謝辞
- 自動文字起こしの不自然な固有名詞を、そのまま正式名称として扱うこと

## 5. 見出しの条件

- 見出しは、議題や記載内容を直接示す日本語にする
- あおり文、キャッチコピー、比喩的な見出しを使わない
- 英語見出し、英語副題、日本語見出しに重ねる英語ラベルを使わない
- 重要度は、言葉を強くするのではなく、順序と階層で示す
- 会議で使われた正式な案件名が確認できる場合は、一般化せず残す

使用できる見出しの例：

- 飲食スペース・グルメ施策
- ホームゲーム集客・広告
- RED LIFE・メールマガジン
- LP・情報発信の整理
- パートナー・新規連携案件
- 次回に向けた主な対応

使用しない見出しの例：

- いま動かなければ、すべてが遅れる
- 次の一手が未来を変える
- 売るのではなく、選ばれる
- 英語だけの見出しや副題

## 6. 残す情報

- 決定したこと
- 決定していないこと
- 判断理由
- 数字、日時、期限
- 正式な案件名
- 担当と関係部署
- 制約、反対意見、実施条件
- 次回に判断すること
- 会議後の具体的な対応

発言順を変えてもよい。ただし、誰の意見かが判断に影響する場合は発言者を残す。

## 7. 削る情報

- 相づち
- 同じ内容の繰り返し
- 画面共有や資料探索の操作会話
- 言い直しだけの発言
- 結論に影響しない雑談
- 内容を増やさない予告、総括、あおり文
- 発言者同士の軽いやり取り

削ることで判断理由、意見の違い、担当の根拠が消える場合は残す。

## 8. 自動文字起こしの扱い

- 固有名詞、金額、日付、人数は推測で補完しない
- 聞き取れない箇所は「要確認」とする
- 正式な数値は、会議資料や管理表と照合する
- 発言から担当者を推測して確定しない
- 認識誤りが多い場合は、発言者名より部署・役割で記載する
- 企画名やサービス名は、会議資料、公式表記、前後の文脈で確認する
- 不確かな名称を一般語へ置き換えて、確認済みに見せない

## 9. 詳細版との使い分け

### 共有版

- 読み手：部内・関係部署
- 目的：内容把握、情報共有、次の対応
- 構成：案件別
- 情報量：要点のみ
- 発言者：必要な場合だけ

### 詳細版

- 読み手：担当者、欠席者、承認者
- 目的：議論の経緯、判断理由、認識差の確認
- 構成：案件別を基本に、必要な発言を補う
- 情報量：背景と選択肢を残す
- 発言者：判断主体が必要な箇所で記載

共有版から詳細版を作るのではなく、文字起こしや原資料から、それぞれの目的に合わせて編集する。

## 10. AIへ依頼するときの指示

```text
次の文字起こしを、部内共有用の議事録に整理してください。

目的：内容把握・情報共有
情報量：要点のみ簡潔に

書式：
■日付 会議名 共有事項
1. 全体概要
2. 主な共有・確認事項
◎案件名
■主な案
・箇条書き
3. 関連案件・新規連携案件
4. 次回に向けた主な対応

ルール：
- 発言順ではなく、案件別に整理する
- 決定、検討、確認、次の対応を混ぜない
- 相づち、言い直し、操作会話、結論に影響しない雑談は削る
- 固有名詞、金額、日付、人数、担当者を推測で補完しない
- 正式名称が確認できる案件は一般化しない
- 本文は短い段落を基本とし、箇条書きは同じ役割でそろえる
- 体言止めを適度に使うが、責任、期限、条件、行動は動詞まで書く
- 不明点は「要確認」と明記する
```

## 11. 最終確認

- タイトルが「■日付・会議名 共有事項」の形になっているか
- 「全体概要」で会議の範囲と重要方針が分かるか
- 案件見出しを「◎」、案件内の案を「■」、列挙を「・」で整理しているか
- 一つの案件が一つのまとまりになっているか
- 決定、方針、検討、確認、次の対応が混ざっていないか
- 見出しだけで議題と内容が分かるか
- あおり文、キャッチコピー、英語見出し、英語副題が残っていないか
- 数字と期限が正式資料と一致しているか
- 担当と完了条件が分かるか
- 自動文字起こしの誤りを推測で埋めていないか
- 正式名称を不必要に一般化していないか
- 次回に何を決め、誰が何を進めるかが分かるか
