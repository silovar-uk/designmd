# 一枚のスライド設計図

> 状態：`experimental`  
> designmd版：2026.08.05-beta  
> 最終更新：2026-08-05  
> 評価期限：説明・報告、説得・提案、読み物・体験の3案件で試行後、stable化・修正・撤回を判断する

この文書は、資料全体の構成を決めた後、PowerPoint上で一枚を組み始める前に使う。

> この設計図は、すべての欄を埋めるためのテンプレートではない。  
> 一枚に必要な部品と、置かない部品を判断するための中間成果物である。

PowerPointの操作へ入る前に、その一枚が誰に何を成立させるのかを決める。ただし、一枚の中心を決めることと、全ページを同じ形にすることを混同しない。

---

## 1. 資料全体と一枚の間をつなぐ

制作は、次の順番で進める。

```text
読み手に起こしたい変化
  ↓
資料全体で採用する問いと中心メッセージ
  ↓
このページの伝達目的
  ↓
このページの役割
  ↓
読み手がこの時点で持つ問い
  ↓
一行での回答
  ↓
根拠・条件・反証
  ↓
表現形式と必要な部品
  ↓
レイアウト
```

タイトルや図を先につくり、後から根拠を当てはめない。

---

## 2. 二つの軸で一枚を定義する

### 軸A｜伝達目的

一枚を見た後、読み手に何を成立させたいかを一つ選ぶ。

| 伝達目的 | 読み手に成立させること | 基本の問い |
|---|---|---|
| 事実共有 | 状況、結果、条件を正確に知る | 何が起きているか |
| 示唆・解釈 | 事実の意味や因果を理解する | この事実から何が言えるか |
| 行動明示 | 次にすること、担当、期限を把握する | 次に何をするか |
| 判断・承認 | 選択、承認、保留、差し戻しを行う | 何を選び、何を決めるか |

伝達目的は、資料全体のモードと一致させつつ、ページごとに変えてよい。

### 軸B｜ページの役割

ページが資料の流れの中で何をするかを選ぶ。

| 上位役割 | 詳細タグの例 | ページの仕事 |
|---|---|---|
| 見る | 観察、事実、証拠 | 対象や状況を確認する |
| 比べる | 問い、比較、反証 | 差、選択肢、別の説明を並べる |
| 考える | 理論、解釈 | 意味、因果、仮説を組み立てる |
| 決める | 判断、提案 | 推奨、選択、承認事項を示す |
| 進める | 次アクション、間、転換、回収 | 次の行動や次ページへつなぐ |

伝達目的とページの役割は別の軸である。

```text
伝達目的：判断・承認
ページの役割：比べる
→ 共通軸で選択肢を比較し、決定を促すページ

伝達目的：示唆・解釈
ページの役割：反証
→ 最初の見立てを別の証拠で更新するページ
```

## 3. 最小版の設計図

まずは次の6項目だけを定める。

```text
伝達目的：
ページの役割：
読み手がこの時点で持つ問い：
一行で答えるなら：
その回答を支える根拠：
最初に検討する形式：
```

この6項目で一枚の骨格を説明できない場合、装飾や細かなレイアウトへ進まない。

### 一行での回答

一行での回答は、必ずしも強い断言やキャッチコピーではない。

- 事実の要約
- 問い
- 比較条件
- 未確定事項
- 複数案
- 反証
- 決めるべきこと

も一枚の中心になり得る。

「一枚一メッセージ」を「一枚一断言」へ変換しない。

## 4. 詳細版の設計図

必要な案件だけ、次を使う。

```text
【一枚の設計図】

ページ番号：
資料全体での位置：
読み手：
使用場面：発表／閲覧／会議／営業／その他

伝達目的：事実共有／示唆・解釈／行動明示／判断・承認
ページの役割：見る／比べる／考える／決める／進める
詳細タグ：

この時点で読み手が持つ問い：
この一枚で答えること：
一行で答えるなら：

根拠：
反証・条件・例外：
必要な固有素材：
最初に検討する形式：

タイトル：
キーメッセージ：
本文・図表：
注釈：
出所：
ノート：

前ページから受け取るもの：
次ページへ渡すもの：
このページで終わらせるもの：

情報密度：低／標準／高
視線の入口：
置かない部品：
```

詳細版は制作ログであり、スライド上にこの項目名を表示するものではない。

## 5. 部品は仕事がある場合だけ置く

一枚の基本部品を、全ページ共通の入力欄にしない。

| 部品 | 主な仕事 | 省略・縮小できる例 |
|---|---|---|
| タイトル | 何について何を示すか伝える | 全面写真の章扉、意図的な間 |
| キーメッセージ | 掲載情報から読み取る意味を示す | 問い、引用、詳細一覧、未確定事項 |
| サブタイトル | 対象範囲、期間、条件を補う | タイトルまたは注釈で十分な場合 |
| ボディ | 根拠、比較、構造、実物を示す | 章扉、単独引用、意図的な余白 |
| 注釈 | 条件、例外、定義を補う | 自明で誤解の余地がない場合 |
| 出所 | 検証可能性を担保する | 自社方針、明示された創作、出典不要の固有情報 |
| 次へのつなぎ | 次の問いや行動を渡す | 単独閲覧ページ、そこで完結する付録 |
| ノート | 背景、因果、留保、話す文章を補う | PPTX納品では原則省略しない |

### 部品監査

各部品について問う。

> この部品を消すと、理解、判断、検証、操作の何が失われるか。

「見栄えが寂しくなる」しか答えられない場合は、削除候補とする。

---

## 6. タイトル、キーメッセージ、本文を重複させない

- **タイトル**：何について、何を示すページか
- **キーメッセージ**：掲載情報から何を読み取るか
- **本文・図表**：事実、根拠、条件、例外
- **ノート**：背景、因果、判断理由、留保、前後の接続

悪い例：

```text
タイトル：来場者数が増加
キーメッセージ：来場者数は増加した
本文：来場者数は前年比で増加した
```

役割を分けた例：

```text
タイトル：ホームゲーム来場者数の前年差
キーメッセージ：休日開催の伸長が、平日開催の減少を上回った
本文・図表：試合別の来場者数、曜日、前年差、条件
ノート：販売開始時期と対戦カードの影響、単純比較の限界
```

キーメッセージが不要なページには置かない。

## 7. 形式は主張ではなく、必要な比較から選ぶ

迷ったときは次を入口にする。

| 読み手が確認するもの | 最初に検討する形式 |
|---|---|
| 正確な値、条件、担当 | 表 |
| 量、差、推移、構成比 | グラフ |
| 因果、流れ、分岐、位置関係 | 図 |
| 定義、短い説明、発言 | テキスト、引用 |
| 現物、画面、人物、空間 | 写真、実画面、実物 |

これは最終形式を自動決定する規則ではない。

- 表で傾向を見せたいならグラフも検討する
- グラフで正確な値を読ませたいなら表も残す
- 図で新しい関係が増えないなら文章へ戻す
- 写真を消しても情報が失われないなら装飾を疑う
- 箇条書きで十分な内容をカードへ変換しない

詳細は [`format-selection.md`](format-selection.md) を参照する。

## 8. PowerPointへ入る前に低忠実度で試す

1. 一行での回答だけを書く
2. 根拠を1〜3群に分ける
3. 白黒の箱だけで配置する
4. 視線の入口と読む順番を確認する
5. 不要な部品を外す
6. その後に色、写真、質感、動きを設計する

この段階では、影、グラデーション、細かな写真加工、アニメーションを確定しない。

白黒の箱を使う目的は、全ページを同じワイヤーフレームへ入れることではない。主張と根拠の関係、情報のまとまり、視線の入口を確認することである。

---

## 9. 一枚のまとまりを設計する

情報量が多い場合、最初に情報を削るのではなく、知覚上のまとまりを確認する。

- 関係するものを近づける
- 同じ役割の形、向き、文字階層をそろえる
- グループ内の余白より、グループ間の余白を広くする
- 一つのまとまりの中にも主役と補助をつくる
- まとまり同士の声量を変える

ごちゃつきは要素数だけでなく、どれとどれが仲間か分からないこと、複数のまとまりが同じ強さで競合することから生じる。

> 情報を減らす前に、仲間をつくる。  
> 仲間をつくったら、順番をつける。

## 10. 10秒テスト

第三者に一枚を10秒だけ見せ、次を確認する。

1. 何についてのページか
2. 中心は何か
3. 根拠はどこか
4. 必要な場合、何を判断・実行すべきか

伝達目的ごとの最低条件：

| 伝達目的 | 最低限答えられる項目 |
|---|---|
| 事実共有 | 1〜3 |
| 示唆・解釈 | 1〜3 |
| 行動明示 | 1〜4 |
| 判断・承認 | 1〜4 |

10秒で細部を理解させるのではない。入口、中心、根拠の位置が分かるかを見る。

## 11. 失敗パターン

### 設計図が新しいテンプレートになる

- 全ページへ同じ欄を置く
- すべてのページにキーメッセージを入れる
- 根拠を必ず三つに分ける
- 同じ白黒ワイヤーフレームを量産する

### メッセージが根拠より先に強くなる

- 事実ページを提案タイトルにする
- 一行で言いやすい内容だけを残す
- 反証や条件を付録へ追い出しすぎる

### 情報を減らすことが目的になる

- 高密度な比較表を理由なく分割する
- 正確な値を消して印象的なグラフだけにする
- 一枚で比較すべき選択肢を別ページへ分ける

### 統一と均質を混同する

統一してよいもの：

- Noto Sans JP
- 色の意味
- 数字や単位の書式
- 出典、注釈、ページ番号の基準
- 図形と矢印の意味

変えてよいもの：

- ページ構造
- 情報密度
- 視線の入口
- 図版の大きさ
- 余白量
- 読む速度

フォントの詳細は [`font-policy.md`](font-policy.md) を参照する。

## 12. 試行と評価

説明・報告、説得・提案、読み物・体験の3案件で記録する。

- 一枚の中心を決める時間が短くなったか
- タイトル、キーメッセージ、本文の重複が減ったか
- 根拠のない強いメッセージが減ったか
- ページの構造が均一にならなかったか
- 不要な部品を外せたか
- 初見の理解が改善したか
- 設計項目が増え、制作時間だけが伸びなかったか

次の条件を満たした場合、stable化を検討する。

- 3案件中2案件以上で構成または初見理解が改善した
- 固定レイアウト化が起きていない
- 一枚の設計時間が過度に増えていない
- 作成者が伝達目的とページの役割を区別できる

次の場合は、項目を縮小または撤回する。

- すべての欄を埋める作業になった
- 形式を先に選び、内容を当てはめるようになった
- 全ページが同じ骨格へ収束した
- チェック項目が増え、理解や判断が改善しなかった
