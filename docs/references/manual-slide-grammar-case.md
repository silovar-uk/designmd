# 事例分析：マニュアル資料のスライド文法

> 状態：reference / case study  
> 最終更新：2026-08-13  
> 対象：ユーザー提供の1600×900 JPEG 9枚  
> 資料表記：『マニュアル通りに人が動けない4つの落とし穴』 / @park_Tivoli

この文書は、特定の色やイラストを模倣するためのスタイルガイドではない。提供された一連のスライドから、社内説明資料へ転用できる**視覚文法**を抽出し、別視点から批判した上で、再利用できる原則へ磨き直すためのケーススタディである。

色値、文字サイズ、面積比は元データではなくJPEGからの目視・画像解析による概算である。正確なテンプレート値として使わない。

---

## 1. 一度目の分析｜ビジュアルシステム設計者の視点

### 1-1. この資料の本当の強さは「1枚」より「連続性」にある

単体のレイアウトだけを見ると、巨大数字、カード、イラスト、矢印という比較的単純な部品でできている。強いのは、同じ四段階を前半と後半で**反転して再利用**している点である。

```text
前半：知ってる？ → 読む？ → わかる？ → 動ける？
      ↓          ↓        ↓          ↓
    落とし穴1   落とし穴2  落とし穴3   落とし穴4

後半：存在を知らせる → 読みたくさせる → わかりやすくする → 動けるようにする
```

前半で覚えた四段階を、後半の改善策でもう一度使う。読み手は新しい分類体系を覚え直さずに済む。デザイン上の反復が、単なる統一感ではなく**理解の足場**になっている。

### 1-2. 色は「色相」より明度差で仕事を分けている

重要なのは水色そのものではない。少数の明度階層に役割を固定している。

- **基底面**：白またはごく淡い寒色。最も大きな面積を取り、情報を受け止める
- **構造面**：基底面より少しだけ差のある淡色カード。グループ化を示す
- **アクセント面**：中程度の彩度を持つ寒色。巨大数字、進捗、矢印など「構造」に使う
- **前景**：ほぼ黒。タイトルと本文を最も強くする
- **イラスト色**：局所的に多色。意味のある例示部分に閉じ込める

JPEGを粗く量子化して見ると、問題提示ページでは淡い寒色の基底面が画面のおよそ6割、さらに薄い構造面が1〜2割程度を占める。改善策ページでは白系の基底面が6割強、淡色カードと薄灰のカードが合わせて2割弱、中彩度のアクセントは数％程度に抑えられている。

ここから得られる原則は「アクセントカラーを少なく使う」だけではない。

> **高彩度を狭く、低彩度を広く使う。**  
> 面積が大きいほどコントラストを弱め、面積が小さいほど強くできる。

巨大数字は面積が大きいが、背景との明度差を抑えることで「大きいのに本文より叫ばない」状態をつくっている。

### 1-3. 文字はサイズの絶対値より「段差」が大きい

1600×900の画像上では、おおむね次のような階層に見える。

- スライドタイトル：約60〜80px級
- カード見出し：約28〜38px級
- 本文：約19〜25px級
- フッター：約13〜17px級
- 巨大数字：約300〜450px級

実制作ではpxを移植せず、本文を1とした相対比で考える。

```text
フッター        0.65〜0.8
本文            1.0
カード見出し    1.4〜1.7
スライドタイトル 2.6〜3.4
巨大な番号・記号 10〜16相当の視覚高
```

強いのは、タイトルを少し大きくした程度ではなく、**本文と主役の間に明確な断崖をつくること**である。巨大数字、タイトル、カード見出し、本文の四段階が一目で分かる。

### 1-4. 余白は「空いている」のではなく、グループ境界として使う

各スライドは情報量が少ないわけではない。文章、カード、イラスト、進捗、巨大数字が共存している。それでも散らかって見えにくいのは、次の余白ルールがあるためである。

- スライド外周に広い安全域がある
- タイトルと説明文は一つの上部グループとして近い
- 下部のカード同士は近いが、上部文章とは大きく離す
- カード内余白を十分取り、カード境界を太線で強調しない
- 「情報がない場所」を、次の意味ブロックとの境界として使う

目安として、左マージンは画面幅の約5〜7％、上端の主タイトル開始は高さの約10〜14％に収まるページが多い。これは固定値ではなく、**外周余白が本文の行間より明らかに大きい**ことが重要である。

### 1-5. 構図には一つの強い方向がある

問題提示ページでは左から右、改善策ページでは「左の段階 → 中央の打ち手 → 右の到達状態」という方向が一貫する。

改善策ページを大きく三分すると、概ね次のような役割になる。

```text
左 25〜30％：段階番号＋タイトル＋既存課題
中 30〜35％：打ち手
右 30〜35％：望ましい状態
残り       ：ガターと外周余白
```

中央から右へ伸びる淡い矢印は、文章を読まなくても「施策によって状態が変わる」ことを先に伝える。矢印自体が主役にならないよう、彩度とコントラストは抑えている。

### 1-6. 斜めのカードが「運動」をつくる

角丸長方形だけでなく、平行四辺形に近い斜めのカードを繰り返している。これによって、静的な社内資料にわずかな前進感が生まれる。

ただし、斜め形状が機能している理由は「おしゃれだから」ではない。

- ステップが進む
- 左から右へ移る
- 障害から解決へ変わる

という資料の内容と方向性が一致しているためである。

### 1-7. イラストは説明の代わりではなく「具体化」に使う

イラストは、主張そのものを担っていない。タイトルや本文で意味を確定した後、

- 探せない
- 読むのがしんどい
- 理解できない
- 行動できない

といった状態を、瞬時に具体化するために置かれている。

つまり役割は decoration ではなく example / state visualization である。

### 1-8. 背景色の反転が章の転換を知らせる

問題側は淡い寒色の全面背景、改善策側は白基調へ切り替わる。これは単なるページバリエーションではなく、

```text
問題を観察するフェーズ
↓
解決策を設計するフェーズ
```

という物語上の切り替えを、ページを読む前に示している。

同じ資料内で背景を変える場合、色を増やすのではなく**フェーズ変更にだけ使う**と統一と変化を両立できる。

## 2. 二人目の批評｜プレゼン編集者・情報設計者の視点

一度目の分析は「なぜ気持ちよく見えるか」に寄りすぎている。社内資料として強くするなら、次を批判的に見る必要がある。

### 2-1. 巨大数字は、意味が薄いページでは装飾に転落する

数字1〜4が「四段階の現在地」を示すため、この資料では意味を持つ。しかし同じ技法を、番号に意味のないページへ移植すると、最も大きな要素が最も重要な情報ではなくなる。

**修正原則**：巨大文字を使うのは、順序、尺度、日付、結論語など、それ自体が意味を持つ場合だけ。

### 2-2. 本文は投影環境では小さくなりやすい

近距離で見る画像としては読みやすいが、会議室後方からの投影では説明文や箇条書きが弱くなる可能性がある。特に問題提示ページは、上部に4行程度の文章を置くため、タイトルとのサイズ差が大きいほど本文が相対的に小さく感じられる。

**修正原則**：本文サイズは見栄えで決めず、閲覧距離を先に決める。投影資料なら説明文をノートへ移す、2枚に分ける、要点だけ残す選択を持つ。

### 2-3. いわゆる汎用イラストは、資料の信頼感と固有性を弱めることがある

状態理解には効く一方、経営会議、法務、事故報告、精密なデータ説明では、イラストの親しみやすさが内容の重さと衝突する場合がある。また、どの会社の資料にも見える危険がある。

**修正原則**：イラストの機能だけを継承し、素材自体は実画面、現場写真、簡潔な図、固有のピクトグラムへ置換できるようにする。

### 2-4. 淡色同士の差は、環境によって消える

淡い背景と淡いカードの差は上品だが、プロジェクター、低輝度ディスプレイ、印刷では境界が消えやすい。

**修正原則**：低コントラスト面は装飾・グループ化に限定し、意味の判別を色差だけに依存させない。余白、位置、見出し、形も併用する。

### 2-5. 「斜め」をルール化しすぎるとテンプレート臭が出る

斜めのカードはこのテーマでは動きを生むが、全案件で使えばスタイルが内容より先に立つ。

**修正原則**：形は意味から選ぶ。進行・変化・方向がない資料では直交グリッドへ戻す。

### 2-6. 右側の理想状態は、根拠と提案を混同しやすい

改善策ページでは、右側に「こうなる」という望ましい状態が大きく置かれる。視覚上は気持ちいいが、施策の効果が検証済みでない場合、提案が事実のように見える。

**修正原則**：右端のカードが「実証された結果」「目標状態」「仮説」のどれかを明示する。色やレイアウトだけで確信度を上げない。

### 2-7. 最終フローチャートは、シリーズの中で急に密度が上がる

全体像を示す価値は高いが、線、分岐、ラベルが増え、前ページまでの大きなタイポグラフィと余白中心のリズムから外れる。

これは失敗とは限らない。むしろ「最後に構造を一望する」役割なら成立する。ただし、本編の結論ページではなく**参照・回収ページ**として扱う方が自然である。

## 3. 批評後の二度目の抽出｜残すもの、変換するもの、捨てるもの

### そのまま残すべき思想

1. **ページ単体ではなく、資料全体で反復を設計する**
2. **色相より明度階層で役割を分ける**
3. **本文と主役のサイズ差を大胆につける**
4. **余白をグループ境界として使う**
5. **一枚に一つ、支配的な読み方向をつくる**
6. **同じモチーフを使うなら、現在地や状態など意味を持たせる**
7. **背景や構図の変化を、物語上の転換へ対応させる**

### 案件ごとに変換すべきもの

- 水色 → 案件のアクセント色。ただし彩度・面積バランスは維持
- いらすと系素材 → 写真、実画面、図、ピクトグラムへ置換可能
- 平行四辺形 → 方向性がある場合だけ使用
- 巨大数字 → 意味のある番号、数値、短語の場合だけ
- 進捗ダイヤ → 段階を覚えてほしいシリーズだけ

### 模倣しないもの

- 正確な色値
- 同じ角度、同じカード寸法
- 毎ページの巨大数字
- 同じ位置へのイラスト固定
- 「白背景＋右に淡色カード」を万能テンプレートにすること

## 4. designmdへ持ち込む結論

この事例をテンプレート名として登録するのではなく、次の二層へ分ける。

```text
共通文法
  ├─ 明度階層
  ├─ 文字サイズ比
  ├─ 余白と近接
  ├─ 読み方向
  ├─ 反復の意味
  └─ フェーズ転換

パターン
  ├─ 段階診断
  ├─ 障害の二例
  ├─ 打ち手→到達状態
  ├─ 現在地ナビ
  ├─ 比較・反転
  └─ 全体フロー
```

共通文法は案件をまたいで使う。パターンは、ページの伝達目的と役割に合う場合だけ選ぶ。
