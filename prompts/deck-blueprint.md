# 複数ページの資料を設計する

以下を、そのままAIへ渡して使う。

```text
以下のガイドを必須要件として参照してください。

資料全体の構成文法：
https://raw.githubusercontent.com/silovar-uk/designmd/main/docs/deck-grammar.md

一枚の視覚文法：
https://raw.githubusercontent.com/silovar-uk/designmd/main/docs/slide-visual-grammar.md

一枚の設計図：
https://raw.githubusercontent.com/silovar-uk/designmd/main/docs/slide-blueprint.md

スライド全般：
https://raw.githubusercontent.com/silovar-uk/designmd/main/docs/slides.md

今回の依頼：
（ここに、資料の目的、読み手、原材料、想定ページ数を記載）

# 最初に決めること

完成スライドを作る前に、次を整理してください。

1. 資料全体の問い
2. 読み手
3. 読後に起こしたい変化
4. 資料全体の中心メッセージ
5. フェーズ
   - 例：問題 → 分析 → 解決 → 回収
6. 各ページの役割
7. 各ページの密度
   - 静 / 標準 / 密 / 動

# Deck Grammar

次を分けてください。

## 固定するもの
- フォント
- 色の意味
- 本文サイズの下限
- 注釈・出所
- 同じ役割の図形
- 余白の基本単位

## 意味がある場合だけ反復するもの
- 現在地ナビ
- 章番号
- ステップ番号
- 比較軸
- 分類記号

反復する場合は「読み手に何を覚えてほしいための反復か」を一文で説明してください。

## 積極的に変えるもの
- 構図
- 情報密度
- 主役の位置
- 主役の種類
- 画像サイズ
- 背景の基調
- タイトルの強度

# 必須ルール

- 一枚の成功要因を全ページのテンプレートへ拡大しない
- 同じ構図を3枚以上連続させないことを初期条件とする
- 巨大数字を3枚以上連続させない
- 同じ左右分割を3枚以上連続させない
- 背景の大きな変更は内容上のフェーズ転換と対応させる
- 全ページを同じ情報密度にしない
- 回収ページへ新しい論点を大量に追加しない
- 強い視覚手法を連続使用する場合は、その反復の意味を説明する
- 指定テンプレートや内容上の理由がある場合は例外にできるが、理由を示す

# 進め方

完成版を一度に作らないでください。

1. ストーリーボードを作る
2. 3〜5枚単位の密度リズムを確認する
3. 代表3ページだけ低忠実度ワイヤーを作る
4. 代表3ページを横に並べ、同じページに見えないかレビューする
5. 必要なら構図、密度、背景、主役位置を変更する
6. その後で残りを制作する

# 出力順

## A. 資料全体の設計
- 問い
- 読み手
- 読後変化
- 中心メッセージ
- フェーズ

## B. ストーリーボード
表形式で以下を示す。
- #
- フェーズ
- 伝達目的
- ページ役割
- 読み手の問い
- 一行での回答
- 意味パターン S1〜S7
- 構図パターン V1〜V6
- 密度：静 / 標準 / 密 / 動
- 主役

## C. Deck Grammar
- 固定するもの
- 意味がある場合だけ反復するもの
- 積極的に変えるもの
- 強い手法の使用回数方針

## D. リズムレビュー
3〜5ページごとに、
- 構図
- 密度
- 主役位置
- 背景基調
が単調になっていないか確認する。

## E. 代表3ページ
完成デザインではなく、白黒の低忠実度ワイヤーフレームを示す。
3ページは異なる役割と構図から選ぶ。

## F. 再レビュー
- 同じ資料に見えるか
- 同じページには見えないか
- 反復に意味があるか
- フェーズ転換が見えるか
- どこを次に直すべきか
```
