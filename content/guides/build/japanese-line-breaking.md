## まず区別する｜「改行できる」と「そこで改行したい」は別

日本語の改行には、少なくとも二つの判断がある。

1. **規則上、改行してよいか**
2. **読み手にとって、そこで改行するのがよいか**

Unicode Line Breaking Algorithm は、文字列から「改行候補」を求めるところまでを扱う。実際にどの候補を選ぶかは、表示幅や文字サイズ、レイアウトを知る上位の組版処理へ委ねられている。

つまり、ブラウザが折り返せる場所は、そのまま編集上の最適解ではない。

このガイドでは、改行を**空いた箱へ文字を入れる処理ではなく、意味のまとまりを視覚的に編集する行為**として扱う。

## 五層で判断する

### 1. 規則｜壊してはいけない境界を守る

最初に、禁則や文字単位として分割できない箇所を守る。句読点、括弧、小書き文字などの扱いは、日本語組版の規則を優先する。

ここは「好み」より先に確認する。

### 2. 語｜名前や語の認識を壊さない

規則上は折り返せても、短い見出しやラベルでは、固有名詞、サービス名、長い外来語、認識に時間がかかる複合語を途中で切ると読みにくくなることがある。

たとえば、狭い見出しで次のように割れる状態は避けたい。

```text
ユーザーエクスペリエ
ンスを改善する
```

ただし、日本語本文のすべての語を英語の単語のように「絶対に分割しない」とはしない。日本語は通常、語の内部にも改行機会を持つ。短い見出し、図表キャプション、ボタン、カード見出しなど、**一目で意味の塊を認識させたい場所ほど保護を強くする**。

### 3. 意味｜文節・フレーズのまとまりを優先する

単語だけでなく、読み手が一度に理解する意味の塊を見る。

```text
改善前
AIがつくった
ページで感じる
日本語改行の
違和感

改善後
AIがつくったページで感じる
日本語改行の違和感
```

改行回数が多いほど丁寧になるわけではない。短い行が続くと、各行が独立した主張のように見え、読みの速度も不必要に止まる。

### 4. リズム｜一行ではなく、複数行を一つの形として見る

見出しでは、個々の行が収まることだけでなく、全体の形を見る。

- 最終行だけ極端に短くないか
- 1語だけ孤立していないか
- 2〜3行で読める内容を4〜5行に割っていないか
- 行ごとに意味がぶつ切りになっていないか
- 改行によって、意図しない語が強調されていないか

CSS Text Level 4 の `text-wrap-style: balance` は、複数行の空き幅を見ながら折り返し位置を選ぶ考え方を持つ。これは、改行を一行ずつではなく全体として扱う方向と一致する。

### 5. 適応｜PCで正しい改行を、スマホへ固定しない

Webでは幅が変わる。PCで美しい位置へ `<br>` を入れても、スマートフォンでは別の不自然さを生む。

強制改行は、意味として必ず切る必要がある場合に限る。単に「この画面幅で見栄えがよかった」という理由で本文へ `<br>` を増やさない。

## 調整の順番｜文字を小さくする前に、何を動かすか

収まらないときは、次の順で調整する。

1. **意味のまとまりを確認する**
2. **文言を短くできるか編集する**
3. **コンテナ幅・余白・レイアウトを見直す**
4. **折り返し候補を調整する**
5. **字間を必要最小限だけ調整する**
6. **短い表示文字に限り、文字サイズを下限内で調整する**
7. **それでも難しければ、一行増えることを許す**

「入りきらないから文字を小さくする」を最初の解決策にしない。

一方で、ヒーロー見出し、短いキャッチコピー、固定面積のサイネージなどでは、**意味の途中で割るより、定めた下限まで少し縮小する方がよい場合がある**。ここは本文と分けて考える。

本文サイズを行ごと・文字列ごとに変えると、読みの一貫性とアクセシビリティを壊しやすい。本文は基本サイズを守り、レイアウト側で解決する。

## Web実装｜使う順番

### 1. 言語を明示する

```html
<html lang="ja">
```

CSSの言語依存処理は、文書の言語が分かるほど適切に働きやすい。日本語のページを無指定にしない。

### 2. 本文に強制改行を埋め込みすぎない

本文では自然な折り返しを基本にする。

```css
.prose {
  line-break: auto;
  word-break: normal;
  overflow-wrap: normal;
}
```

`overflow-wrap: anywhere` や `word-break: break-all` を、日本語本文の通常設定として使わない。URL、コード、非常に長い識別子など、オーバーフロー回避が優先される箇所へ限定する。

### 3. 短い見出しは、フレーズ単位の折り返しを試す

CSS Text Level 4 では `word-break: auto-phrase` が定義されている。対応するユーザーエージェントでは、言語固有の解析によって自然なフレーズ内の折り返しを抑える。

```css
.heading {
  word-break: auto-phrase;
  text-wrap: balance;
}
```

ただし、CSS Text Level 4 は2026年8月時点で Working Draft であり、ブラウザ実装差がある。**必須機能として依存しない**。

```css
.heading {
  word-break: normal;
  text-wrap: balance;
}

@supports (word-break: auto-phrase) {
  .heading {
    word-break: auto-phrase;
  }
}
```

### 4. 編集上重要な境界だけ `<wbr>` を使う

固定された短い見出しで、どうしても望ましい候補を示したい場合は、強制改行 `<br>` より optional な `<wbr>` を優先する。

```html
<h1>日本語の改行を<wbr>意味から設計する</h1>
```

幅があれば一行のまま、必要な場合だけ候補位置で折り返せる。

### 5. 固有名詞の保護は局所的に行う

```html
<span class="keep-together">浦和レッズ</span>
```

```css
.keep-together {
  white-space: nowrap;
}
```

ページ全体を `keep-all` にしない。保護する理由を説明できる語だけに使う。

## 見出しの文字サイズを自動調整するとき

可変サイズそのものを禁止しない。ただし、文字列が変わるたびに「入るまで縮める」実装は避ける。

推奨する条件：

- 対象は短い見出し、KV、固定面積の表示
- 最小文字サイズを先に決める
- 1段階または少数段階で調整する
- 下限を超えたら縮小を続けず、行数を増やす
- 200%拡大、スマートフォン、長い固有名詞で再確認する

```css
.hero-title {
  font-size: clamp(2rem, 6vw, 5rem);
  line-height: 1.12;
  text-wrap: balance;
}
```

`clamp()` は「文字列を検出して無限に縮める」仕組みではない。表示条件に応じて、あらかじめ決めた範囲で変化させるために使う。

## AIへ渡す判断規則

```text
日本語の改行は、空いた幅へ機械的に詰めるのではなく、次の順で判断する。

1. 禁則・文字単位を守る。
2. 短い見出しでは固有名詞、外来語、複合語を不自然に分割しない。
3. 単語だけでなく、文節・意味のまとまりを優先する。
4. 短い行を連発せず、複数行全体のリズムを見る。
5. PCの見栄えだけを理由に <br> を固定しない。
6. 収まらない場合は、文言→幅・余白→折り返し→字間→表示文字のサイズ、の順に調整する。
7. 本文を収めるために文字を縮小しない。短い見出しだけ、下限を決めてサイズ調整を許可する。
8. 最後にスマートフォン、狭幅、200%拡大で確認する。
```

## レビュー｜5つだけ見る

1. **語**：固有名詞や認識しにくい語が途中で割れていないか
2. **意味**：文節・フレーズの途中に不自然な切れ目がないか
3. **リズム**：短い行や一語だけの最終行が連続していないか
4. **適応**：`<br>` がPC専用の見栄え調整になっていないか
5. **下限**：収めるために本文文字を小さくしていないか

## このガイドを experimental にする理由

禁則や言語指定は既存の組版・Web仕様に根拠がある。一方、どの複合語を保護するか、見出しを何行まで許すか、字間と文字サイズのどちらを先に動かすかは、媒体、フォント、閲覧環境で変わる。

さらに `word-break: auto-phrase` は CSS Text Level 4 の Working Draft に含まれる機能であり、実装差を前提に扱う必要がある。

### stable化の条件

- Web記事、スライド／PDF、カード・バナーの3種類以上で試す
- PC、スマートフォン、狭幅、200%拡大を含む実寸確認を残す
- 不自然な語中改行、極端な短行、オーバーフロー、文字サイズ下限違反を比較する
- 手動 `<br>` の削減が、意味の誤読やレイアウト崩れを増やしていない
- `auto-phrase` 非対応環境でも読める

評価期限：2026-11-30。

### 撤回・修正条件

- フレーズ保護によってオーバーフローが増える
- 文字サイズ調整が端末ごとの大きな見た目差を生む
- 固有名詞保護が増えすぎ、本文の自然な折り返しを妨げる
- ブラウザ実装差によって再現性が保てない

その場合は、「本文は通常の折り返し、短い表示文字だけ編集判断を加える」という最小ルールへ戻す。
